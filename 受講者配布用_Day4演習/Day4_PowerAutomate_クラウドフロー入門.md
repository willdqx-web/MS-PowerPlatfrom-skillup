## 0. 今日のゴール

Day1・Day2 の PAD は「自分の PC の中」の自動化でした。今日からは **クラウド上で動く自動化
（クラウドフロー）**を作ります。PC を閉じていても、クラウドが自動で処理してくれます。

今日の業務シナリオは「**現場から電話で来た設計変更依頼を、フォームのように 1 件登録する**」です。
手で `設計変更管理.xlsx` を開いて入力していた作業を、クラウドフローに置き換えます。
さらに「影響度が高い依頼は、登録と同時に管理者へ通知する」ところまで作ります。

- クラウドフローの 3 つのトリガー（手動・自動・スケジュール）の違いが分かる
- **PAD（ローカル）とクラウドフローの違い**が説明できる
- 手動トリガーのフローを作り、**メールを送って**テスト実行できる
- **動的コンテンツ**と**式**の違いが分かり、日付を式で作れる
- **変数**と**条件分岐**を使える
- **Excel テーブルに行を追加**できる（`T_設計変更申請`／`通知ログ`）
- **実行履歴**で成功/失敗と各アクションの中身を確認できる

まず1章を読んでから、2章以降のステップ演習に進んでください。

## 1. 概念の解説

### 1-1. クラウドフローとは（PAD との違い）

Power Automate には 2 種類あります。Day1・2 で使った **PAD（デスクトップ）**と、今日から使う
**クラウドフロー**です。同じ「Power Automate」でも、動く場所と得意分野が違います。

| | PAD（デスクトップ） | クラウドフロー |
|---|---|---|
| 動く場所 | 自分の PC の中 | **クラウド上**（PC を閉じても動く） |
| つなぎ方 | 画面を操作する | **コネクタ**で正規に接続する |
| 得意 | 画面操作、ローカルのファイル | Excel(OneDrive)・Outlook・Forms などの連携 |
| 例え | VBA マクロ | 「アプリ同士をつなぐ自動処理」 |

> Day2 で学んだ判断基準を思い出してください。**コネクタがある相手（Excel・Outlook・Forms）は
> クラウド**が正解でした。今日はまさにそのクラウド側を作ります。

### 1-2. トリガーとアクション

クラウドフローは「**トリガー**（きっかけ）」＋「**アクション**（やること）」で組み立てます。

- **トリガー**: フローが動き出すきっかけ。1 つのフローに 1 個。
- **アクション**: きっかけの後に順番に実行する処理。いくつでも並べられる。

トリガーには 3 種類あります。

| トリガーの種類 | 動き出すきっかけ | 例 |
|----------------|------------------|-----|
| **手動（インスタント）** | 自分がボタンを押したとき | 今日作るフロー |
| **自動** | 何かが起きたとき | Forms に回答が来たら（Day7） |
| **スケジュール** | 決めた時刻に | 毎朝 9 時に集計（Day5・6） |

### 1-3. 動的コンテンツと式

アクションの入力欄には、固定の文字だけでなく「**動的コンテンツ**」や「**式**」を入れられます。

| | 何か | 例 |
|---|------|-----|
| 動的コンテンツ | 前のステップで得られた値 | トリガーで入力された「申請ID」 |
| 式（関数） | その場で計算して作る値 | `utcNow()`（今の日時）、`formatDateTime(...)`（日付の整形） |

> VBA でいえば、動的コンテンツは「変数の中身」、式は「関数の呼び出し」に近いです。

### 1-4. 変数

クラウドフローでも変数が使えます。使う前に必ず「**変数を初期化する**」で型と初期値を決めます
（VBA の `Dim` に相当）。その後「**変数の設定**」で値を変えます。

### 1-5. 条件（分岐）

「**条件**」アクションで、Yes/No の 2 方向に分岐します（VBA の `If ... Then ... Else`）。
今日は「影響度＝高なら通知する、そうでなければしない」の分岐に使います。

### 1-6. Excel コネクタの注意（テーブルが必要）

クラウドフローから Excel を読み書きするには、**データが「テーブル」になっている**必要があります。
Day3 で `T_設計変更申請` をテーブルにしたのはこのためです。今日は「**表に行を追加**」で
1 行足します。

## 2. ステップ演習1: 初めての手動トリガーフロー（目安40分）

まずは「ボタンを押すとメールが届く」だけの、一番簡単なフローを作ります。

1. ブラウザで `https://make.powerautomate.com` を開きサインインする
2. 左メニュー「＋作成」→「**インスタント クラウド フロー**」を選ぶ
3. フロー名を `Day4_変更依頼登録` とし、トリガーは「**フローを手動でトリガーします**」を
   選んで「作成」
4. 「＋新しいステップ」→「**Office 365 Outlook**」→「**メールの送信 (V2)**」を追加する
5. 設定する
   - 宛先: **自分のメールアドレス**（テストなので自分宛にします）
   - 件名: `テスト送信`
   - 本文: `初めてのクラウドフローです`
6. 右上「保存」→「**テスト**」→「手動」→「テスト」→「フローの実行」→「完了」
7. 自分のメールに `テスト送信` が届けば成功です

> **なぜ自分宛にするのか**: 架空の宛先に送ると届きませんし、実在しない相手に送るのも避けたい
> ためです。テスト段階では自分宛にして、動作を目で確認します。

### 2-1. 実行履歴を見る

1. フローの詳細ページを開き、「**28 日間の実行履歴**」から今の実行をクリックする
2. 各アクションが緑のチェック（成功）になっていることを確認する
3. 「メールの送信 (V2)」をクリックし、**入力**（宛先・件名・本文）を確認する

> 実行履歴は、うまくいかないときの最重要ツールです。どのアクションで、どんな値で失敗したかが
> すべてここに残ります。

## 3. ステップ演習2: トリガーに入力欄を付け、変数と式を使う（目安50分）

電話で聞いた依頼内容を、ボタンを押すときに入力できるようにします。

### 3-1. トリガーに入力を追加する

1. `Day4_変更依頼登録` を編集する
2. トリガー「フローを手動でトリガーします」を開き、「**入力の追加**」で次を**テキスト**として追加する
   - `申請ID` / `申請者社員ID` / `案件コード` / `変更種別` / `影響度` / `変更概要`

### 3-2. 申請日を「式」で作る

登録日は自動で入れます。手入力させません。

1. 「＋新しいステップ」→「**作成**」（データ操作）を追加する
2. 「作成」の入力欄をクリックし、「**式**」タブに次を入力して OK
   ```
   convertFromUtc(utcNow(),'Tokyo Standard Time','yyyy-MM-dd')
   ```
   → これで「今日の日付（日本時間）」が `2026-07-23` の形で作られます
3. この「作成」の名前を `申請日` に変更しておく（アクション名の … →「名前の変更」）

> **なぜ式で作るのか**: 人が日付を手入力すると、書き方がバラバラ（2026/7/3 と 2026-07-03 等）に
> なります。式で作れば常に同じ形式になり、後の集計が安定します。

### 3-3. 変数で通知メッセージを組み立てる

1. トリガーのすぐ下に「**変数を初期化する**」を追加
   - 名前: `通知本文` / 種類: `文字列` / 値: 空
2. 「作成（申請日）」の下に「**変数の設定**」を追加
   - 名前: `通知本文`
   - 値: 動的コンテンツと固定文字を組み合わせて次のように作る
     ```
     案件 [案件コード] の変更依頼（[変更種別]）が登録されました。影響度: [影響度]
     ```
     ※ `[案件コード]` などの部分は、動的コンテンツから「申請ID」等を選んで挿入します

## 4. ステップ演習3: 条件で分岐して通知を出し分ける（目安50分）

「影響度＝高」のときだけ、管理者（今回は自分宛）に通知します。あわせて、**通知したことを
Excel の `通知ログ` テーブルにも記録**します（後でレビューする人が「条件が正しく効いたか」を
確認できるようにするためです）。

### 4-1. 通知ログ テーブルを用意する（Excel 側の準備）

1. `設計変更管理.xlsx` を開き、新しいシート `通知ログ` を追加する
2. A1 から横に `申請ID` / `通知日時` / `区分` と入力する
3. その 3 セルを選び「挿入」→「テーブル」でテーブル化し、テーブル名を `通知ログ` にする
   （見出しだけでデータ 0 行のテーブルで OK）

### 4-2. 条件分岐を作る

1. フローに戻り、「＋新しいステップ」→「**条件**」を追加する
2. 条件を設定する
   - 左: 動的コンテンツの「**影響度**」
   - 演算子: **次の値に等しい**
   - 右: `高`
3. 「**はいの場合**」の中に 2 つのアクションを入れる
   1. 「メールの送信 (V2)」
      - 宛先: 自分のメール
      - 件名: `【至急】高影響度の変更依頼`
      - 本文: 動的コンテンツの「**通知本文**」（変数）
   2. 「Excel Online (Business)」→「**表に行を追加**」
      - ファイル: `設計変更管理.xlsx` / テーブル: `通知ログ`
      - 申請ID: 動的コンテンツ「申請ID」
      - 通知日時: 式 `convertFromUtc(utcNow(),'Tokyo Standard Time','yyyy-MM-dd HH:mm')`
      - 区分: 固定文字 `高影響度通知`
4. 「**いいえの場合**」は空のままでよい（通知もログもしない）

#### 確認用の答え合わせ（テスト実行）
- 影響度に `高` を入れて実行 → **メールが届き**、`通知ログ` に 1 行増える
- 影響度に `中` を入れて実行 → **メールは届かず**、`通知ログ` は増えない
- どちらの実行も、実行履歴では**成功（緑）**になる（「いいえ」側は何もしないだけで、失敗ではない）

## 5. ステップ演習4: Excel テーブルに行を追加する（目安50分）

いよいよ、依頼内容を `設計変更管理.xlsx` の `T_設計変更申請` に登録します。

1. 「条件」の**後ろ**（分岐の外）に「＋新しいステップ」→「**Excel Online (Business)**」→
   「**表に行を追加**」を追加する
2. 設定する
   - 場所: `OneDrive for Business`
   - ドキュメント ライブラリ: `OneDrive`
   - ファイル: `設計変更管理.xlsx` を選ぶ
   - テーブル: `T_設計変更申請` を選ぶ
   → テーブルの各列が入力欄として表示されます
3. 各列に値を割り当てる（動的コンテンツを使う）

   | 列 | 入れる値 |
   |----|----------|
   | 申請ID | 動的コンテンツ「申請ID」 |
   | 申請日 | 動的コンテンツ「出力」（作成＝申請日） |
   | 申請者社員ID | 動的コンテンツ「申請者社員ID」 |
   | 案件コード | 動的コンテンツ「案件コード」 |
   | 変更種別 | 動的コンテンツ「変更種別」 |
   | 変更概要 | 動的コンテンツ「変更概要」 |
   | 影響度 | 動的コンテンツ「影響度」 |
   | ステータス | 固定文字 `申請中` |

   （希望完了日・承認者・承認日・判定は空のままでよい）
4. 保存して、**2 件**テスト実行する（この 2 件が、後のレビューの判定材料になります）。
   - 1 件目（影響度・高）: 申請ID `A014` / 申請者社員ID `E103` / 案件コード `P003` /
     変更種別 `図面修正` / 影響度 `高` / 変更概要 `取付角度の修正`
   - 2 件目（影響度・中）: 申請ID `A015` / 申請者社員ID `E105` / 案件コード `P002` /
     変更種別 `部品変更` / 影響度 `中` / 変更概要 `ねじの変更`

#### 確認用の答え合わせ
- `T_設計変更申請` の**末尾に A014・A015 の 2 行が増える**（Day3 の 13 行 → 15 行）
- 申請日にはテスト実行した当日の日付（日本時間）が入る／ステータスは `申請中`
- `通知ログ` には **A014（高）だけ 1 行**あり、**A015（中）は無い**（＝条件分岐が正しく効いた証拠）
- A014 のときは `【至急】…` のメールが届く／A015 では届かない
- 実行履歴がすべて成功（緑）になっている

## 6. 応用課題（自力で取り組んでください）

ここからは手順の細かい指示はありません。1〜5 章を活かして、自分で考えて取り組んでください。

1. **入力チェックを 1 つ足す**
   「申請ID」が空のときは登録せず、「申請IDは必須です」というメールだけを送るようにする。
   （ヒント: もう 1 つ「条件」を使う。`empty()` 関数や「次の値に等しい 空」で判定できます）

2. **登録した申請者に受付メールを送る**
   本来は申請者本人へ「受け付けました」と返したいところ。今回は仕組みを試すだけなので、
   宛先は自分宛のまま、本文に「申請ID・案件コード・申請日」を差し込んで送る。

3. **（発展）通知先を影響度で変える**
   影響度＝高なら件名を `【至急】`、中・低なら件名を `【通常】` にして、どちらも送るようにする
   （「いいえの場合」にも通知を入れる）。

#### 応用課題の答え合わせ（例）
- 課題 1: 申請IDを空にして実行 → 行は増えず、「必須です」メールだけ届く
- 課題 2: 受付メールの本文に、入力した申請ID・案件コード・当日の申請日が入っている

## 7. 保存方法（今日の成果物）

今日の環境では、クラウドフローそのものをファイルに書き出すことはできません（「エクスポート」に
その項目がありません）。そこで、**フローが動いた結果を Excel に残して提出**します。今日のフローは
結果が `設計変更管理.xlsx` に現れるように作ってあるので、**追加の提出作業はほぼありません**。

### 提出の手順

1. ステップ演習4 のテストを **A014（高）・A015（中）の 2 件**、実行しておく
   （これが「トリガー・行追加・条件分岐が正しく動いた証拠」になります）
2. `設計変更管理.xlsx` は Day3 で評価担当に共有済みなので、**追加の共有操作は不要**
   （まだ共有していない場合は、OneDrive でブックを右クリック →「共有」→ 評価担当を「表示可能」で追加）

これだけで提出完了です。評価担当は共有ブックの `T_設計変更申請` と `通知ログ` を見て、
フローの挙動（行追加・条件分岐）を確認します。

> **なぜフロー本体を出さないのか**: この環境ではフローをファイルとして書き出せないためです。
> 代わりに「結果を見れば挙動が分かる」ように設計しています。実務でも「作った自動化が
> 正しい結果を残しているか」で品質を判断することは多く、良い練習になります。

### 提出物（＝共有済み Excel の状態）

- `T_設計変更申請`: A014・A015 が追加され、全 15 行になっている
- `通知ログ`: A014（高）だけが記録され、A015（中）は無い
