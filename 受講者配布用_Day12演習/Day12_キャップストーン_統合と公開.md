## 2. テストと期待結果

`day12_要件定義.md` の「4. テスト」「5. 期待結果」の通りに実行してください。要点:

- 受付から R01（P001・高）・R02（P001・中）・R03（P002・低）を登録
- R01 を承認、R02 を却下、R03 は依頼中のまま
- 集計 → `出図集計` が **P001=2 / P002=1**
- 存在しない依頼ID `RZZ` で承認処理 → `失敗ログ` に 1 件（例外処理の確認）

## 3. 最終レビュー用ルーブリック（自己評価＋提出後の判定）

各観点を「できた／一部／未」で自己採点してください。**機能要件と運用品質の両方**が
合格ラインです。

| 観点 | 判定基準 | 自己評価 |
|------|----------|----------|
| 機能要件（通貫） | 受付〜承認〜集計が要件どおり通貫して動く | ◯ / △ / × |
| データ設計 | テーブル・列が要件どおり、日付書式・入力規則が設定されている | ◯ / △ / × |
| 承認の書き戻し | R01=承認済/承認、R02=却下/却下、R03=依頼中 | ◯ / △ / × |
| 集計 | `出図集計` が P001=2 / P002=1 | ◯ / △ / × |
| エラー処理・例外設計 | `失敗ログ` に RZZ が残り、無言停止しない | ◯ / △ / × |
| 共有・引継ぎ | 共有設定済み・引継ぎ文書が実用的 | ◯ / △ / × |
| ツール選定 | Forms/Power Apps/クラウド/PAD の使い分けを説明できる | ◯ / △ / × |
| 公開 | 想定利用者が実際に使える状態で公開されている | ◯ / △ / × |

> **合格ライン**: 「機能要件（通貫）」「承認の書き戻し」「集計」「エラー処理・例外設計」
> 「共有・引継ぎ」がすべて ◯。ここが「動くだけでなく、実務に耐える」の境界です。
