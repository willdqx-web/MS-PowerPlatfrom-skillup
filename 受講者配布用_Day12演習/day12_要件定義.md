# Day12 キャップストーン 要件定義書（図面出図依頼システム）

あなたは「みらい設計エンジニアリング」の設計補助担当として、次の業務の内製化を依頼された。
これまで 11 日間で学んだことを総動員して、**要件から一から**組み上げること。

---

## 1. 背景・目的

設計案件で「図面の出図（正式発行）依頼」が増え、Excel とメールの手作業が限界に来ている。
- 依頼がメールで散在し、記録が残らない
- 誰が承認したか追えない
- 案件ごとの出図依頼件数を集計するのに手間がかかる

これを Power Platform で内製化し、**依頼受付 → 承認 → 集計 → 公開**を通貫させる。

## 3. 機能要件

1. **受付（入口）**: 依頼者が出図依頼を出せる入口を作る（**Forms または Power Apps のどちらでもよい**）。
   受け付けたら `T_出図依頼` に記録し、依頼IDを自動採番、ステータスは `依頼中`。
2. **承認**: 承認者がレビューして承認/却下し、結果（ステータス・判定・承認者・承認日）を
   `T_出図依頼` に書き戻す。**処理が失敗しても `失敗ログ` に残し、通知する**こと（例外処理）。
3. **集計**: 案件ごとの出図依頼件数を `出図集計` に転記する。
4. **公開・引継ぎ**: 入口（アプリ/フォーム）を利用者に、ブックを評価担当に共有し、
   **引継ぎドキュメント**（Day11 のテンプレートに準拠）を残す。

## 4. テスト（この通り実行して結果を残すこと）

受付から次の 3 件を登録する。

| 依頼ID | 案件コード | 優先度 | 図面番号 |
|--------|-----------|--------|----------|
| R01 | P001 | 高 | DWG-001 |
| R02 | P001 | 中 | DWG-002 |
| R03 | P002 | 低 | DWG-003 |

承認処理を実行する。
- R01 → **承認**（ステータス `承認済` / 判定 `承認`）
- R02 → **却下**（ステータス `却下` / 判定 `却下`）
- R03 → 承認処理せず `依頼中` のまま

集計を実行する。

## 5. 期待結果（自己評価・AI 評価の答え合わせ）

- `T_出図依頼`: R01=承認済/承認、R02=却下/却下、R03=依頼中
- `出図集計`: **P001=2 件 / P002=1 件**
- `失敗ログ`: 承認処理をわざと存在しない依頼ID（例 `RZZ`）で実行し、1 件記録されていること
- 引継ぎドキュメントが埋まっていること
