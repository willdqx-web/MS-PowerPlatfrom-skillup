## 0. 今日のゴール

Day5 は「集計して転記」でした。今日は、集計結果を**読みやすいレポートに整えて配る**ところまで
やります。設計補助業務での「月次報告メール」を自動化するイメージです。

- **式（関数）**をもう一歩使いこなす（日付整形・文字結合・条件式）
- **「作成（Compose）」**で途中の値を確認しながらデバッグできる
- **データ操作「選択（Select）」**で、表の形を整えられる
- **「HTML テーブルの作成」**で、メールに貼れるきれいな表を作れる
- 整形したレポートを**メールで送信**できる

まず1章を読んでから、2章以降のステップ演習に進んでください。

## 1. 概念の解説

### 1-1. 式（関数）をもう一歩

Day4・5 で `utcNow()` や `convertFromUtc(...)` を使いました。今日はもう少し増やします。

| 式 | 何をするか | 例 |
|----|-----------|-----|
| `formatDateTime(値,'yyyy年MM月')` | 日付を好きな形に整える | `2026年06月` |
| `concat('A','B')` | 文字をつなげる | `concat('案件',案件コード)` |
| `if(条件,真の値,偽の値)` | 条件で値を分ける | `if(greater(工数,25),'超過','OK')` |

### 1-2. 「作成（Compose）」はデバッグの友

「**作成**」アクションは、入れた値をそのまま出力するだけのアクションです。一見地味ですが、
「この式は何になる？」を**途中で確認**するのに最適です。VBA の `Debug.Print` に近い使い方です。

### 1-3. データ操作「選択（Select）」で形を整える

表のデータを、必要な列だけ・好きな見出しに**作り替える**のが「**選択（Select）**」です。
例えば `案件別集計`（案件コード・合計工数・件数）を、レポート用に「案件・工数(h)・件数」の
見出しに整えられます。

### 1-4. 「HTML テーブルの作成」

配列データを、メールに貼れる**HTML の表**に変換するアクションです。Select で整えたデータを
渡すと、そのままきれいな表になります。

## 2. ステップ演習1: 作業分類ごとに工数を集計する（目安50分）

まず、機械的に確認できる集計を 1 つ作ります。「作業分類（設計/検図/修正/打合せ）ごとの工数合計」
を出して、`分類別集計` テーブルに書き込みます。

### 2-1. 置き場所を作る

1. `設計変更管理.xlsx` に新しいシート `分類別集計` を追加
2. A1 から `作業分類` / `合計工数` と入力し、テーブル化（テーブル名 `分類別集計`）

### 2-2. フローを作る

`https://make.powerautomate.com` で「インスタント クラウド フロー」を作り、
`Day6_工数レポート` とします。

「設計」の工数合計を出す手順（他の分類も同じ要領で繰り返します）:

1. 「表内に存在する行を一覧表示」（`T_工数実績`）
   - フィルター クエリ: `作業分類 eq '設計'`
2. 「変数を初期化する」: `合計` / 整数 / 0
3. 「それぞれに適用する」→ 中で「変数を大きくする」`合計` ＋＝ 動的コンテンツ「工数」
   - **同時実行制御をオフ（次数 1）**にする（Day5 で学んだ落とし穴）
4. ループの後ろで「表に行を追加」（`分類別集計`）
   - 作業分類: `設計`（固定）／合計工数: 変数「合計」
5. 同じ流れを **検図・修正・打合せ**の分も作る（フィルターと固定文字を変える）

#### 確認用の答え合わせ（分類別集計）
| 作業分類 | 合計工数 |
|----------|----------|
| 設計 | 82 |
| 検図 | 22 |
| 修正 | 14 |
| 打合せ | 8 |

（4 つ合わせて 126。Day5 の全工数合計と一致します）

## 3. ステップ演習2: 案件別集計をレポート表にしてメールする（目安50分）

Day5 で作った `案件別集計` を、きれいな表にしてメールで送ります。

### 3-1. データを読み込んで「選択」で整える

1. `Day6_工数レポート` に続けて「表内に存在する行を一覧表示」（`案件別集計`）を追加
2. 「データ操作」→「**選択**」を追加
   - 開始: 動的コンテンツ「value」（案件別集計の出力）
   - マップ（テキストモードで見出しと値を指定）:
     | 見出し | 値（動的コンテンツ） |
     |--------|---------------------|
     | 案件 | 案件コード |
     | 工数(h) | 合計工数 |
     | 件数 | 件数 |

### 3-2. HTML テーブルにする

1. 「データ操作」→「**HTML テーブルの作成**」を追加
   - 開始: 「選択」の出力
   - 列: 自動

### 3-3. 式でタイトルを作ってメールする

1. 「作成」を追加し、式でレポート見出しを作る
   ```
   concat('工数集計レポート（', formatDateTime(convertFromUtc(utcNow(),'Tokyo Standard Time'),'yyyy年MM月'), '）')
   ```
2. 「メールの送信 (V2)」を追加
   - 宛先: 自分のメール
   - 件名: 「作成」の出力（レポート見出し）
   - 本文: 動的コンテンツ「**出力**」（HTML テーブルの作成の結果）
   - 詳細オプションで「**HTML でメールを送る**」相当（本文をリッチテキスト/HTML）にする
3. 保存してテスト実行し、自分宛に**案件別の表が入ったメール**が届くことを確認する

#### 確認用の答え合わせ
- 届いたメールの表に、P001〜P006 の 6 行（工数 30/20/16/24/14/22）が並ぶ
- 件名が「工数集計レポート（2026年〇月）」の形になっている

## 4. 応用課題（自力で取り組んでください）

1. **超過マークを付ける**
   `案件別集計` の各案件に、`if(greater(合計工数,25),'超過','OK')` で判定列を足して
   レポート表に「判定」列を追加する（P001 だけ「超過」になる）。
2. **「作成」でデバッグする**
   HTML テーブルの前に「作成」を置いて「選択」の結果を出力し、実行履歴で中身を確認する。
3. **（発展）本文を整える**
   HTML の表の前に、式で作った「対象月」「総工数（126h）」の一文を添える。

#### 応用課題の答え合わせ
- 課題 1: レポート表の「判定」で「超過」になるのは **P001 のみ**
- 課題 3: 総工数の値は **126**
