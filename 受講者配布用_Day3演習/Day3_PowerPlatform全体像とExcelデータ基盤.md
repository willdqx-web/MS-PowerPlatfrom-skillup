## 1. 概念の解説

### 1-1. Power Platform とは（VBA・Excel の経験と結びつける）

これまで Excel の関数やマクロ（VBA）で自動化してきた作業を、**クラウド上で、複数の人・
複数のアプリをまたいで**自動化・アプリ化できるようにするのが Power Platform です。
今回主に使う 4 つの役割分担は次のとおりです。

| ツール | ひとことで言うと | 今回の役割 |
|--------|------------------|-----------|
| **Excel（OneDrive）** | クラウド上の「表（データ置き場）」 | すべてのデータの土台 |
| **Power Automate**（PA） | 決まった処理を自動で流す「マクロのクラウド版」 | 集計・転記・通知・承認 |
| **Power Apps** | 入力画面（アプリ）を作る道具 | 申請の入力 UI |
| **Forms** | アンケート/申請フォーム | 申請の入口 |

> 中心は **Power Automate と Power Apps**、データの置き場所が **Excel（OneDrive）**、
> 申請の入口が **Forms** です。

### 1-2. なぜ OneDrive の Excel なのか（本来は別のものが向いている）

業務データの置き場所には、本来 **SharePoint リスト**や **Dataverse** といった「ちゃんとした
データベース」が向いています。しかし**今回の環境では SharePoint も Teams も使えません**。
そこで、標準ライセンスで確実に使える **OneDrive 上の Excel** をデータベース代わりに使います。

ここで大事なのは、**Excel をデータベース代わりに使うことの限界を最初に知っておく**ことです。

| 観点 | ちゃんとした DB（SharePoint 等） | Excel |
|------|-------------------------------|-------|
| 型の強制 | 日付列に文字を入れられない等、**型を強制**する | **強制しない**（何でも入る） |
| 大量データ | サーバー側で絞り込める | **苦手**（後日 Day10 で「委任」の限界として扱う） |
| 同時編集 | 複数人でも安全 | ぶつかると壊れやすい |

だから今回は、**足りない「型の強制」を、自分でデータの入力規則を設定して補います**。
これが今日の一番のポイントです。

### 1-3. 「範囲」ではなく「テーブル」にする

Excel の表には「ただのセルの範囲」と「**テーブル**」の 2 種類があります。
Power Automate や Power Apps がデータを読み書きするには、**必ず「テーブル」にしておく**必要が
あります（ただの範囲は読めません）。

テーブルにすると、次の利点があります。

- 行を足すと自動で範囲が広がる（数式やアプリの参照がずれない）
- 列に名前（見出し）が付き、PA から「この列」と指定できる
- 見た目も整い、フィルターが付く

> VBA でいう「名前付き範囲」をもっと強力にしたもの、と考えてください。

### 1-4. 擬似的に「型」を持たせる 2 つの道具

Excel は型を強制しませんが、次の 2 つで「型のようなもの」を再現します。

| やりたいこと | 使う機能 | 例 |
|--------------|----------|-----|
| 決まった選択肢から選ばせる（選択肢型の代わり） | **データの入力規則（リスト）** | ステータス＝申請中/承認待ち/承認済/却下 |
| 日付として扱わせる（日付型の代わり） | **セルの表示形式＝日付** | 申請日、希望完了日 |

> **なぜ入力規則を設定するのか**: 例えばステータスを自由入力にすると、「承認済」「承認済み」
> 「approved」などの表記ゆれが混ざり、後の集計や自動化が壊れます。ドロップダウンにして
> おけば、決まった値しか入らず、事故を防げます。

### 1-5. マスタと明細を分ける

データは「**マスタ**（あまり変わらない基本情報）」と「**明細**（日々増えていく記録）」に
分けて持つのが基本です。今回は次のように分けます。

- マスタ: `M_部署`（部署）、`M_担当者`（社員）、`M_案件`（案件）
- 明細: `T_設計変更申請`（設計変更の依頼が日々たまっていく）

明細には「部署コード」だけを持たせ、部署名などの詳細はマスタ側に置きます。部署名が変わっても
**マスタ 1 か所を直すだけ**で済みます（Excel の VLOOKUP と同じ考え方です）。

## 2. ステップ演習1: 環境確認と OneDrive にブックを作る（目安30分）

### 2-1. Power Platform にサインインできるか確認する

1. ブラウザで `https://make.powerapps.com` を開き、会社のアカウントでサインインする
2. 同様に `https://make.powerautomate.com` も開けることを確認する
   → どちらも開ければ、後日 Power Apps と Power Automate を作る準備ができています
3. 開けない場合は、管理者にライセンス付与を確認してもらってください

### 2-2. OneDrive に空のブックを作る

1. ブラウザで `https://www.office.com` を開き、サインインする
2. 左のアプリ一覧から **OneDrive** を開く
3. 「＋新規作成」→「**Excel ブック**」をクリックする
   → ブラウザ上（Excel for the web）で新しいブックが開きます
4. 左上のファイル名（既定は「ブック」）をクリックし、`設計変更管理` に変更する
   → これで OneDrive 上に `設計変更管理.xlsx` ができました。以降の作業はすべてこのブックの中で行います

> **なぜ OneDrive 上に作るのか**: 後日 Power Automate / Power Apps がこのブックを読みに来ます。
> クラウド（OneDrive）に置いていないと、それらのツールから接続できません。

## 3. ステップ演習2: マスタをテーブル化してデータを入れる（目安60分）

`M_部署` と `M_担当者` を作ります。

### 3-1. M_部署 を作る

1. シート見出し（下部のタブ）を右クリック →「名前の変更」で、シート名を `M_部署` にする
2. `day3_部署マスタ.csv` をメモ帳か Excel で開き、中身（見出し＋5 行）をコピーする
3. `M_部署` シートの A1 セルに貼り付ける
4. 貼り付けた表の中の任意のセルを選び、「**挿入**」タブ →「**テーブル**」をクリックする
   （または Ctrl+T）
5. 「先頭行をテーブルの見出しとして使用する」に**チェック**して OK
   → 表がテーブルになり、見出しにフィルターの▼が付きます
6. 「**テーブル デザイン**」タブの左端「テーブル名」を `M_部署` に変更する
   → **このテーブル名が、後で Power Automate から指定する名前になります。必ず設定してください**

#### 確認用の答え合わせ（M_部署）
- 行数: **5 行**（見出しを除く）／ テーブル名: `M_部署`

### 3-2. M_担当者 を作る（データの入力規則を体験する）

1. 新しいシートを追加（下部の「＋」）し、シート名を `M_担当者` にする
2. `day3_担当者マスタ.csv`（12 行）を A1 に貼り付ける
3. 3-1 と同じ手順でテーブル化し、テーブル名を `M_担当者` にする
4. **「役割」列にドロップダウンを設定する**（擬似的な選択肢型）
   1. 「役割」列のデータ部分（見出しの下、12 行分）を選択する
   2. 「**データ**」タブ →「**データの入力規則**」を開く
   3. 「入力値の種類」を「**リスト**」にする
   4. 「元の値」に次を入力（カンマ区切り）
      ```
      課長,部長,設計担当,設計補助,品証担当,生技担当,総務担当
      ```
   5. OK する → セルを選ぶとドロップダウンの▼が出れば成功
5. 試しに「役割」のセルで、一覧にない文字（例: `テスト`）を入力してみる
   → **エラーで弾かれる**ことを確認する（これが「型を強制する」ということ）。確認後、元に戻す

#### 確認用の答え合わせ（M_担当者）
- 行数: **12 行**
- 「役割 = 設計補助」の人: **2 名**（中村 彩 / 加藤 美穂）
- 「部署コード = D01」の人: **3 名**（田中 誠 / 山本 拓也 / 中村 彩）

## 4. ステップ演習3: 明細テーブルを作り、フィルターで確認する（目安60分）

本カリキュラムの主役、`T_設計変更申請` を作ります。

### 4-1. T_設計変更申請 をテーブル化する

1. 新しいシートを追加し、シート名を `T_設計変更申請` にする
2. `day3_設計変更申請_初期データ.csv`（12 行）を A1 に貼り付ける
3. テーブル化し、テーブル名を `T_設計変更申請` にする

### 4-2. 日付列を「日付」書式にする

1. 「申請日」「希望完了日」「承認日」の 3 列のデータ部分をそれぞれ選択する
2. 「ホーム」タブの数値書式（既定「標準」）を「**短い日付形式**」に変更する
   → 日付として右寄せ表示になれば OK

> **なぜ書式を整えるのか**: 後で「今月分だけ集計」といった処理をするとき、日付として
> 認識されている必要があります。文字列のままだと日付の比較ができません。

### 4-3. 選択肢列にドロップダウンを設定する

3-2 と同じ「データの入力規則（リスト）」を、次の 4 列に設定します。

| 列 | 元の値（カンマ区切り） |
|----|------------------------|
| 変更種別 | `仕様変更,部品変更,図面修正,コスト変更` |
| 影響度 | `高,中,低` |
| ステータス | `申請中,承認待ち,承認済,却下` |
| 判定 | `承認,却下` |

### 4-4. フィルターで件数を確認する

SharePoint の「ビュー」に相当することを、Excel では**テーブルのフィルター**で行います。

1. 「ステータス」見出しの▼をクリックし、「申請中」だけにチェックして絞り込む
2. 画面右下のステータスバー（または行番号）で件数を数える
3. 確認したらフィルターを解除する（▼→「すべて選択」）

#### 確認用の答え合わせ（T_設計変更申請）
| 絞り込み条件 | 件数 |
|--------------|------|
| 全件 | 12 |
| ステータス = 承認済 | 5 |
| ステータス = 申請中 | 4 |
| ステータス = 承認待ち | 2 |
| ステータス = 却下 | 1 |
| 影響度 = 高 | 3 |

## 6. 保存方法（今日の成果物）

今日の成果物は、OneDrive 上のブック **`設計変更管理.xlsx`**（中に 4 つのテーブル）です。
Excel for the web は**自動保存**なので、保存ボタンを押す必要はありません。

### 提出は「ブックを共有するだけ」

スクリーンショットは要りません。次のどちらか **1 手**で提出できます。

- **方法A（推奨）**: OneDrive で `設計変更管理.xlsx` を右クリック →「共有」→ 評価担当
  （指定されたアカウント）を「**表示可能**」で追加する
- 方法B: OneDrive で `設計変更管理.xlsx` を選び「**ダウンロード**」して、その .xlsx を提出する

評価担当は、共有された（または提出された）ブックから、テーブル・データ・入力規則・日付書式を
直接確認します。

> **なぜ共有で提出するのか**: クラウドの成果物は、ファイルで渡すより「共有して見てもらう」のが
> 実務の基本です。この「共有」は **Day11 で学ぶ『共有・権限・引継ぎ設計』**の予行でもあります。
